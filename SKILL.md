# Reel Studio

You turn whatever the user brings — a CapCut draft, an evening filmed on two cameras (a long vlog, or a lively reel cut to a music track), camera takes nobody has cut yet, voice lines recorded for narration, screen recordings, screenshots and renders, or a whole pool of material for a series — into finished vertical reels in Remotion: their cut (or a cut they approved), clean voice, calm captions, directed motion scenes, a quiet lo-fi bed, a 2K render with a loudness and dropped-frame check, and covers on request.

Reply in the user's language; code and file names in English. Every rule here was paid for on a real production; `references/pitfalls/` says how.

## 0. Paths, environment, shell

- `cd <project>` first; scripts by absolute path: `S=~/.claude/skills/reel-studio/scripts` (and `LUT=<cube>` only for log footage — D-Log, S-Log, V-Log: ask the user when the inventory sheet looks flat and grey; `$LUT` wherever a command takes one, per-camera LUTs: `--lut-map`; Rec.709 / phone footage needs none; a DJI clip's own colour profile — read from its djmd track — decides first: Normal gets none, D-Log / D-Log M that camera's DJI cube when it is installed (`assets/luts/README.md`), HLG the HDR LUT). Python with `python3 -I`; scripts that need Vision / numpy / Whisper use `work/venv/bin/python`, DeepFilterNet steps `work/dfvenv/bin/python`, speech recognition `work/gigvenv/bin/python` (GigaAM v3 for Russian; `transcribe.py --lang en …` switches to Whisper in `work/venv` by itself). **Memory guard (macOS) — every step that can take GBs runs under `mem_guard.py`** (kills the command's whole process tree past `--max-gb` or when the machine has less than 4 GB left, exit 137, prints the peak as `MEM_GUARD: …`): a model that takes all the memory freezes the whole machine, the user's apps included (Linux: no guard, watch the size of what you start). The Python steps re-run themselves under it (flags `--max-gb N --min-free-gb 4 --no-guard`; defaults in GB): `transcribe_gigaam.py` / `transcribe.py` 6, `voice_clean.py` (= `voice_isolate.sh`) 8, `dualmic.py` 8, `dialogue.py` 10, `person_matte.py` 10, `ears.py` 6, `sfx_find.py` 4, `vlm_describe.py` 12; `render.sh` wraps Remotion (`MAX_GB=12`). Not wrapped, measured small: ffmpeg proxies (≈ 2 GB), `people_zones.py` / `face_zones.py` (Apple Vision, ≈ 0.1 GB). Anything new and heavy: `python3 -I $S/mem_guard.py --max-gb N --min-free-gb 4 -- <cmd>`. Exit 137 = the guard stopped it: read its message, ask the user to close apps, retry — never lower `--min-free-gb`, never `--no-guard`; if it refuses to start for lack of free memory, wait. DeepFilterNet needs ≈ 1 GB per minute of audio, so `voicelib.df_run` feeds it 2-minute pieces. Optional: `$S/vlm_describe.py` (jobs JSON → JSONL) describes frames with Qwen3-VL-8B 4-bit (env `~/.cache/reel-studio/vlmvenv`, ≈ 5.4 GB model, fetch command in `setup_env.sh` output; ask the user first). Shell scripts take the project dir first and want absolute output paths.
- **Dependencies, per OS**: `python3 -I $S/deps.py` checks everything (tools, ffmpeg filters, node, uv, the python envs) and prints what this platform cannot run; `--install` installs it (brew / apt / dnf / pacman, uv, the envs; root commands only via password-less sudo, else they are listed for the user). macOS on Apple Silicon runs everything; Intel Mac: no MLX (Whisper as openai-whisper, no Qwen3-VL; GigaAM runs on the CPU everywhere); Linux / WSL2: also no Apple Vision (face/people zones, cut-outs → 16:9 canvas or crop keys by hand; the title-behind matte runs BiRefNet on CPU, slowly), software decode, no memory guard; Windows: WSL2 only. Tell the user before relying on a part their platform lacks.
- `$S/setup_env.sh <project>` → `ENV_OK` once per project: links `work/venv`, `work/dfvenv`, `work/gigvenv` (and `vlmvenv`) to the shared environments in `~/.cache/reel-studio/` and copies LUTs and fonts there. On a new machine it installs the environments and fonts (≈ 5 min); GigaAM v3's ONNX model (≈ 1 GB) and Silero VAD (≈ 2 MB) download from Hugging Face on the first Russian transcription, Whisper's (≈ 1.6 GB) on the first one in another language, DeepFilterNet's (≈ 8 MB) on the first isolation — say so before starting.
- `python3 -I $S/doctor.py <project>` at any point: what exists, what is stale or broken, and the `NEXT:` step. `render.sh` runs it as a gate. After editing the skill itself: `python3 -I $S/selfcheck.py` → `SELFCHECK_OK`.
- Every number (frames, levels, layout) lives in `references/craft/numbers.json`; `numbers.md` and the template's `numbers.ts` are generated from it (`$S/numbers_gen.py`).
- zsh traps that bite ad-hoc commands: an empty glob aborts the command (`setopt null_glob` or `(N)`), `$W:$H` is a modifier (write `${W}:${H}`), relative output paths break in scripts that `cd`, two `make_proxies` runs at once are refused (lock) — use `--res both`.

## 1. Start: what did the user bring?

1. A new folder per video or series (never the previous video's folder). Where: `python3 -I $S/projects_dir.py --name video_<topic>` → `SUGGEST <path>` — by default the folder Claude Code is open in (that folder itself when it is empty, next to it when it is a previous project, else a subfolder in it), or the folder the user chose to keep projects in (`--set <dir>`, `$REEL_STUDIO_PROJECTS`). Always ask before creating it (AskUserQuestion: the suggested path first, "another folder" via Other; offer to remember a folder they name), then `$S/new_project.sh <path> [episodes]` → `PROJECT_OK`. Start ⏳ `$S/setup_env.sh <project>` and ⏳ `$S/scaffold.sh <project>` (npm, ≈ 3–4 min, `SCAFFOLD_OK`) in the background right away. A project on an external volume (exFAT: 1 MB clusters, AppleDouble `._*` files next to everything) works as is: scaffold keeps `node_modules` on the internal disk behind a link — never run `npm` inside `reel/` there (`pitfalls/environment-and-shell.md`).
2. Bring the material in: `python3 -I $S/ingest.py <project> <folders|files…> --dry-run`, check the mapping, run without it (pictures, voice and recordings are copied under safe ASCII names; camera clips stay on the volume and are used by path).
3. Look at everything: `python3 -I $S/inventory.py <project> <project>/assets <camera clips or folders>` → `work/inventory/inventory.md` (duration, orientation, fps / VFR, sound level, camera, LUT, notes) and the sheets `camera.jpg` / `screen.jpg` / `images.jpg` (`_1`, `_2` … past 36 tiles). Read them, then the entry below.

| the user brings | read | the entry ends with |
|---|---|---|
| a CapCut draft | `references/inputs/capcut-draft.md` | `work/cutlist.json` from the draft |
| camera takes nobody has cut | `references/inputs/raw-takes.md` | an approved `work/plan.json` → `work/cutlist.json` |

| pictures only, no voice | `references/inputs/images-only.md` | lines to record, or a silent `cutlist.json` on the beat grid |

| a short lively reel cut to a music track («движовый рилс», «кучей событий») | `references/inputs/action-reel.md` | `work/track_beats.json` + `work/gen_action.py` → `shotsData.ts` (no cut list; renders `Action2K`) |

For a CapCut draft the order is different: `capcut_export.py --list` → intake → export → inventory on the cut list's `sources` (ingest only what the user hands over separately). Mixed material is the normal case — combine the entries. Do not scout footage folders to guess the material before the user names it.

**"То же что в прошлый раз"** = the same pipeline and look on new material: read the previous project's (the newest in the projects folder) `NOTES.md` and `work/intake.json`, offer its answers as the defaults (with a different music preset), reuse its palette and the scene files worth copying — in a new folder.

## 2. Intake (first run in a folder)

One AskUserQuestion, at most three questions; the settled defaults (calm phrase captions, DeepFilterNet voice, profanity as a soft bleep + asterisks) are named in the question text so the user can override them via "Other":

1. Output: 2K only / 1080 + 2K / 1080 only (the user publishes 2K). Format: vertical 9:16 (default) — or 16:9 for a long vlog, 4:5 / 1:1 on request → `"canvas"` in intake.json (scaffold.sh and cut_from_transcript.py read it).
2. Music bed: a track the user puts in `assets/music` / procedural lo-fi (preset warm / night / bright / dusk — a new one per video) / none. Offer the track first: the procedural bed is recognisably the same in every video («такой же как всегда») and lo-fi is the wrong genre for a promo; for the calm devlogs it was accepted.
3. Extra material: unused clips as b-roll, screenshots, the article or post behind the video, lines the user can still record. Ask for every missing screenshot or picture **by name** before building the scenes ("скинь скрин дашборда Tripo с ценой") — never fill the gap with an invented one.

For a CapCut draft confirm the draft in the same message; for raw takes and voiceover the structure is a separate approval (the entry files say when). Save answers to `work/intake.json` (`draft, output, canvas, music, voice, subtitles, profanity, extras, article, related`); if it exists, skip the questions.

## 3. Core pipeline (every entry continues here with its cut list)

⏳ = runs in the background while you continue; wait for the marker before the step that needs it.

1. **Voice** — `$S/voice_isolate.sh <project> [--lav <TX folder>] <speech sources>` → `VOICE_DONE` (`voice_clean.py`: per source it measures SNR and clipping and does only what is needed — adeclip where it clipped, DeepFilterNet limited so the room stays ≈ 48 dB under the voice, nothing in a quiet room; ≈ 5 s per minute; skip what the entry already restored). `--lav`: the DJI transmitter's own 32-bit float files when the user has them (synced automatically). Two lav mics on the camera's L/R: `work/dfvenv/bin/python -I $S/dualmic.py <project> --cutlist work/cutlist.json <clips…>` → `DUALMIC_DONE` instead (each mic restored on its own, then automixed). No EQ, compression or levels here — all of that happens once, in the dialogue stem (step 6). How the sound is built and why: `references/craft/audio.md`.
2. **People → crop** (a 9:16 canvas with landscape camera clips — the usual case) — `work/venv/bin/python -I $S/people_zones.py --sheet` → `PEOPLE_ZONES_DONE`, `work/people_zones.json` (Apple Vision finds the people in every used second of the source, ≈ 0.3 s per second; the crop centre follows them, a pan when they move) + `work/people/sheet_*.jpg` with the crop drawn in red. Look at the sheets BEFORE encoding; fix a wrong subject with `"cropX": 0.3` (or `[0.6, 0.3]` for a pan) in that range's plan.json opts and re-run. make_proxies refuses to crop without it (`--centre-crop` only when the user accepts the centre).
3. ⏳ **Proxies** — `python3 -I $S/make_proxies.py --res both --voice-dir work/voice/out --trim-to-cutlist 2 [--lut "$LUT"] [--extra work/broll/x.mov@12-20 …]` → `PROXIES_DONE` (one decode for 1080 and 2K; `--res 1080` for "1080 only"). ≈ 2.5 s per second of DJI 4K footage for both sizes; check `df -h /` first. Camera clips (any video but a screen recording) get the 9:16 crop from the people zones and the LUT when one is given; everything else keeps its aspect at canvas width. HDR sources (HLG / PQ: iPhone «HDR video», a camera in HLG mode — `inventory.md` flags them) get the HDR → Rec.709 LUT automatically (`hdr_lut.py`, matched to Apple's own conversion); without it they look grey and pale. Re-runs re-encode only what changed (per-folder `.manifest.json`); a missing source exits 1 — never render black. Files appear in `reel/public` only when complete. Night footage: `python3 -I $S/night_lift.py <project>` → `NIGHT_LIFT_DONE` lifts the shadows of dark clips in place (re-run after make_proxies re-encodes one).
4. **Timeline** (after `PROXIES_DONE`; `SCAFFOLD_OK` is needed from step 8 on) — `python3 -I $S/gen_timeline.py [--xfade 7] [--punch 1.2]` → `TIMELINE_DONE`, `reel/src/Timeline.tsx` (7-frame dissolve on every cut; a few cuts may get another seam — `"transition"` `whip` / `push` / `blur` / `leak` / `wipe` / `bodywipe` / `match` / `cut`, `references/craft/transitions.md`; CapCut speeds as `playbackRate`, the draft's own framing; punch zoom only for raw takes) + `work/timeline_zoom.json`. `match` / `bodywipe` cuts: `work/venv/bin/python -I $S/seams.py <project>` → `SEAMS_DONE`, then `gen_timeline.py` again. `SEAM BUDGET` lines are errors: alternate.
5. **Transcribe + captions** — `work/gigvenv/bin/python -I $S/transcribe.py --lang ru` → `TRANSCRIBE_DONE` (GigaAM on the exact timeline audio: gaps, speed changes, muted segments and CapCut voiceovers included; word ends are ±0.1–0.26 s. Russian; another language: `--lang en` / `de` … → Whisper), `python3 -I $S/make_captions.py` → `CAPTIONS_DONE` (pages ≤ 8 words / 3.4 s / 54 characters, swears masked per the intake), `python3 -I $S/tl_words.py` → `TL_WORDS_DONE` (word → frame, with `brands.json` and patches applied). Read every page against the audio or the script; fixes go into `work/caption_patches.json` (`drop`, `drop_at`, `replace`, `replace_at`), never into generated JSON. Bleeps: raw takes and voiceover get `work/bleeps.json` from `cut_from_transcript.py`; a CapCut draft from `python3 -I $S/bleeps_from_timeline.py` → `BLEEPS_DONE`. Skip this step for a silent cut list.
6. **Dialogue stem + music + SFX** — `work/dfvenv/bin/python -I $S/dialogue.py <project>` → `DIALOGUE_DONE` (after the timeline and the bleeps list; skip for a silent cut list): the whole dialogue as one processed file `reel/public/audio/dialogue.wav` — every cut crossfaded, room tone in the gaps, takes levelled, one EQ / compressor / de-esser chain, bleeps inside; it prints the EQ moves, LRA and true peak (`Clip` then mutes the proxies, `<Dialogue />` plays the stem). The voice booms, has a room tail or drifts within a take: `voice_probe.py` → `eq_test.py --try …` (an A/B MP3 of the candidates on 30 s, ≈ 5 s to make) → the user picks → `work/voice_tune.json` (narrow resonance notches, expander, slow leveler — all off without the file) → `dialogue.py` again (`craft/audio.md` «Optional voice tools»). Event vlogs: `--bridge` carries each scene's own sound across its scene changes (J/L cuts, `transitions.md` §2). `$S/make_bed.sh <project> <preset>` → `BED_OK`, `reel/public/audio/lofi_bed.wav` + `work/beats.json` (length: the cut list + 15 s, or pass seconds before the preset); a user track: `ffmpeg -i assets/music/<track> -ar 48000 -c:a pcm_s16le reel/public/audio/lofi_bed.wav` (`MusicBed` sets the levels and the end fade). `$S/make_sfx.sh <project>` → `SFX_OK`, `audio/sfx/` (all local): tick, pop, done, whoosh, softwhoosh, hit, shutter, rewind, riser, beep, powerdown; whoosh / softwhoosh / pop / hit in three variants that `R.sfx` cycles — the same sample twice in a row reads as a template. With earshot installed (`deps.py --with sound`) they are designed sounds from its bank, otherwise synthesized; a real recording of something the camera missed: `sfx_find.py` (Openverse, CC0 / CC BY) → `R.sfx(at, "real_<name>")` (`craft/audio.md` «Sound effects»).
7. **Face zones** (talking-head shots only) — `work/venv/bin/python -I $S/face_zones.py` → `FACE_ZONES_DONE`, `work/face_zones.json` in final screen coordinates (punch included).
8. **Scenes → Reel.tsx** — `references/craft/storyboard.md` (what goes where), `references/craft/motion-design.md` (how it moves), `references/craft/scenes.md` (the generator and the kit). Write `work/gen_reel.py` from `assets/examples/gen_reel*.example.py` on top of `scripts/reelgen.py`: anchors are `R.fw("слово")`, never typed frame numbers; cutaways and boards are widened around cuts automatically; `R.cutaway(..., behind={"title": …})` puts a title behind the person (person_matte.py: BiRefNet cutout incl. headphones and props, ≈ 0.9 s per frame, weights ≈ 420 MB on first use; place from `common.title_place`). Then `python3 -I work/gen_reel.py && (cd reel && npx tsc --noEmit -p .)` and `python3 -I $S/lint_reel.py <project>` → `LINT_OK`.
9. **QA** — `python3 -I $S/doctor.py <project>`; `$S/qa_sheet.sh <project> qa1 <frames…>` (16-tile pages in `work/stills/`): the hook, every tag, every element mid-animation, each cutaway in/out, 3 consecutive frames of every transition, every state change of a motion scene, the end. Fix face overlaps, stray talking-head frames, cut-off text. Watch motion scenes as a short render (`npx remotion render Reel out/demo/x.mp4 --frames=a-b`), not only as stills. Before sending a render, go through it yourself with timecodes. **Not sure which option is better** (a look, a caption style, a cut point, the bed level, a voice setting): never a full render per idea — a few seconds of each variant with `$S/render_part.sh` (or one source clip with different `--vf`) → `python3 -I $S/ab_video.py` (numbered cards + beeps, or `--grid` side by side), audio-only questions with `ab.py` / `eq_test.py`; version 1 = как сейчас; send, ask «1 или 2?», write the answer down (`references/craft/ab.md`).
10. ⏳ **Render** — `$S/render.sh <project> Reel2K <abs>/out/<name>_2k.mp4` (and/or `Reel` → `<name>_1080.mp4` per the intake) → `RENDER_DONE` (≈ 2 min per minute, one Chrome tab, temp bundle in `work/tmp`). It refuses when `doctor.py --pre-render` finds errors (`FORCE=1` only when the user accepts a known issue), sets the mix to −16 LUFS with a static gain and a true-peak limiter, encodes the sound once (AAC 320k; Remotion renders PCM), fails beyond ±0.5 LU or on a broken or short file, and prints `audio_qa.py`'s line (LRA, true peak, digital silence, spectrum, clicks at the cuts) — read its warnings. `GLITCH_SCAN BAD n` lists frames: look at them in a sheet — a whip, a flash peak or a hard montage cut can trip it; real dropouts mean a re-render. Bleeps are already in the dialogue stem; `bleep.py` is only for an old project without one. Then `python3 -I $S/motion_gate.py <project> <render>` → `MOTION_GATE_DONE`: look at `work/qa/cuts_*.jpg` (every cut, frames −2…+1) and the `FROZEN` stretches; on the first full render let a fresh subagent review it (`transitions.md` §5); with earshot, `python3 -I $S/ears.py <project> <render>` → `EARS_DONE` listens to it: SFX cues not heard or off their frame, and `work/qa/ears.png`. Move the previous version to `out/prev/` (or keep `_vN` files when the user compares versions). A censored second version of the same cut (for family, YouTube): `references/craft/censor.md`. Deliver only the full-size files — no compressed or preview copies unless asked; files over 30 MB are visible only in the desktop app — say so.
11. **Cover** (on request; offer it for a series) — two kinds, offer both: a cut-out hero on a flat colour (`CoverFrame`) and a plate generated from a real frame with `$S/codex_image.sh -o covers/gen -n <name> -r <frame.png> "<prompt>"` (`ArtCover`; text always stays in Remotion) — only when `deps.py` shows `codex (covers)` OK; otherwise offer `CoverFrame` and say generated plates need the Codex CLI (`deps.py --install --with covers`, then `codex login`). `references/craft/covers.md`, `$S/cover.sh`.

**Re-cut = re-run** (the user reviews in rounds: "сократи до 2:30", "убери плашку"): edit `work/plan.json` (or the draft) → `cut_from_transcript.py` (or `capcut_export.py`) → `dualmic.py --cutlist` (new windows of lav clips) → `people_zones.py --sheet` (scans only new seconds) → `make_proxies.py --res both` (re-encodes only grown or changed windows, crops and mixes) → `night_lift.py` → `gen_timeline.py` → `transcribe.py` → `make_captions.py` → `tl_words.py` → `bleeps_from_timeline.py` (drafts) → `dialogue.py` → `face_zones.py` → `work/gen_reel.py` → `doctor.py` → QA → render. `doctor.py` names what is still stale. `caption_patches.json`, `brands.json`, `plan.json` and `gen_reel.py` carry the human decisions; nothing generated is edited by hand.

## 4. Non-negotiables (why: `references/pitfalls/`)

- The user's cut is final — the CapCut edit (segments, mutes, speeds, framing) or the plan they approved; never trim speech to fit graphics. When asked to shorten, cut whole clauses at real pauses and list what was cut with timecodes.
- Graphics never cover the face; captions never fight with cards; cards go where `face_zones.json` says it is free; close-ups get `Stage` / `SplitStage` instead of a card.
- A cutaway or board covers the whole cut it straddles (`numbers.md`), shows a different framing than the talking head, and shows who or what the sentence is about.
- Audio: restore once and only as much as the source needs (limited DeepFilterNet, never ffmpeg denoisers, never digital silence), one dialogue stem with crossfaded cuts and ONE processing chain, static-gain loudness with a true-peak limiter (not loudnorm), one lossy encode at the very end, music ≈ 20 LU under speech, soft bleeps, quiet SFX with a different sound per kind of action.
- Captions: calm phrases, no word highlighting, no progress bar or persistent UI chrome; consecutive phrases soft-swap (a fade to zero between two phrases is the "blinking line").
- Cuts are softened (7-frame dissolve, a hand-off of the same object, a rare whip); flashes stay under 0.45 opacity; a reel that opens on a cutaway fades from black.
- Alternate: most cuts stay plain, an effect seam or accent marks a real change and has plain cuts around it — never a whoosh, whip, RGB split or flash on every action (`transitions.md` §0; the generators' `SEAM BUDGET` / `FX BUDGET` lines are errors).
- No `backdrop-filter`, no `mix-blend-mode`, no glows, no emoji in UI text; one render tab; nothing ships with a broken file or unexplained `GLITCH_SCAN` frames — single bad frames read as "blinking cards".
- No references to other videos inside a video; the user links related reels in Instagram. "часть 2" in a title is fine.
- Facts and numbers only from the transcript, the user's screenshots or files you checked; placeholders look generic and are listed in the hand-off. Never render secrets from session recordings or transcripts.

## 5. Hand-off

Report: what the reel is made of (sources, chapters, scenes), what was cut and where it can be restored (timecodes), facts on screen and their sources, invented placeholders and what would replace them, loudness and glitch-scan results, where the files are (desktop-only above 30 MB), how to open Studio (`cd reel && npx remotion studio`). Keep `NOTES.md` up to date (decisions, dropped material, how to re-run).
