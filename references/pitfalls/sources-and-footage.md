# Sources and footage

Camera files, external volume, screen recordings, file names, voiceover files, crops. Each item cost real time on a production (2026-10-09 … 2026-10-21); read the file of the area you are about to touch.

- **Log footage looks flat.** DJI Osmo Pocket / Action shoot D-Log. The draft's `effects` with type `lut` names the `.cube`; `capcut_export.py` resolves it (CapCut `Resources/Lut`, `~/Downloads`). Burn it into proxies; Chrome cannot colour-manage.
- **DJI files have a second video stream** (tiny preview). Any explicit mapping must use `-map 0:v:0`, otherwise ffmpeg fails with "Could not find tag for codec h264 in stream #1".
- **HEVC 10-bit 3K source** → always proxy to H.264 yuv420p. Keep native 1728x3072 in mind: 2K (1440x2560) is a real downscale, 4K would be an upscale.
- **External volume** (`/Volumes/...`) may be unmounted. `capcut_export.py` warns; stop and ask instead of silently rendering black.
- Sources in CapCut's temp folder (`/var/folders/.../TemporaryItems/NSIRD_screencaptureui_*`, screenshots dragged straight into CapCut) are not readable. Ask the user to put every screenshot into `assets/screens/`.
- DJI shoots 29.97 fps; `-r 30` duplicates one frame a second. Invisible on a talking head, a visible hitch on a slow pan (sea, drone, walking). For muted b-roll encode with `setpts=PTS/1.001` + `-r 30 -fps_mode cfr` (0.1 % speed-up, no duplicates). Speech clips keep the duplicate (audio sync matters more).
- Claude Code session transcripts (`~/.claude/projects/*/*.jsonl`) can contain passwords the user pasted. When recreating a chat on screen, paraphrase the brief and never render credentials. Prefer the user's own screenshots of the chat (they choose what to show).
- Long one-shot takes (6–7 min) must not be proxied in full: `make_proxies.py --trim-to-cutlist 2` encodes only the used window and records offsets; cutaways from the unused part: `--extra "<take>@<start>-<end>"` (birthday encoded four multi-minute clips twice to use a few seconds of each before windows existed).
- **DJI counters repeat across days** (`_0005_` exists for 24.09 and 30.09): never key thumbnails or proxies by the 4-digit number alone. `clipid.py` is the single id rule and aborts on a collision inside one project; `ingest.py --camera link` names the second link `…_0005b_D.MP4` (no copying), or copy one file under that name.
- **Non-ASCII source names** (macOS screen recordings «Запись экрана — … в 00.52.26.mov», «Снимок экрана …»). The external volume stores them NFD; a path typed/pasted as NFC does not open (`No such file or directory`), and `clip_id()` yields a Cyrillic id. `ingest.py` copies them under ASCII names (`assets/screenrec/rec_YYYYMMDD_HHMMSS.mov`, `assets/screens/shot_…png`) after NFC-normalising; run it before any other script touches them.
- **Silent screen recordings** have an audio track of pure silence; Whisper fills it with «Продолжение следует…» / «Субтитры сделал …» every 30 s. Do not transcribe recordings that have no speech; check `ffmpeg -af volumedetect` first (mean_volume −91 dB = silence).
- **Raw-takes inventory before planning**: one graded frame per camera clip plus a transcript of every clip with sound is enough to classify takes (talking head, over-the-shoulder b-roll, acting) and to plan with second-accurate beats — `inventory.py` makes the sheets and the table, `transcribe_parakeet.py` the transcripts. ffmpeg here has no `drawtext`: tiles carry no labels, the table order is the tile order.
- **Screen recordings as b-roll**: `make_proxies.py` now scales non-DJI extras to the canvas *width* keeping their aspect (a landscape recording used to be squashed into 1080×1920) and never applies the camera LUT to them. For a full-frame vertical use of a landscape recording, pre-crop it with ffmpeg (`crop=876:1558:<x>:0`) into `work/broll/` and pass that file as an extra; check the first seconds — macOS leaves the Control Center / volume menu and the cursor in the recording for ~6 s (trimBefore accordingly).
- **AppleDouble sidecars on the external volume**: next to every `Запись экрана ….mov` there is a 4 KB `._Запись экрана ….mov`. A Python `os.listdir` loop copied the sidecar first and then skipped the real file ("already exists") → `moov atom not found`. Skip names starting with `.` and check the copied size. Shell globs (`*.mov`) do not match them, Python does. `ingest.py` and `inventory.py` skip them.
- **macOS screenshot/recording names contain U+00A0** (`2026-10-10 в\xa013.58.13.mov`), so a regex with a literal space does not match; use `\s+`. `ingest.py` treats it as a space.
- **Voiceovers recorded in CapCut** live in `…/com.lveditor.draft/<draft>/audio_record/VoiceoverN_*.aac`; the user copies the good takes into `assets/voiceover/`, but the draft still holds their trims (`capcut_export.py --draft <name>` → audio tracks with `srcStart`/`dur`). Read those trims: they say which part of a take the user considers good (a false start with swearing is cut off there). Whisper adds «Спасибо за субтитры…» to the silent tail of a take.
- **Screen-recording crops**: check the crop over time, not on one frame — a speech bubble appeared above the character two seconds in and got cut by the window edge; a 9:16 full-height crop needs `zoom 1.0` when UI text touches both edges.
- **Horizontal camera clips** (`DJI_*` 3840×2160) used to be squashed into 9:16; `make_proxies` centre-crops them now. For another crop position grade and crop by hand (`lut3d` + `crop=1215:2160:x:0`) and save without the `DJI_` prefix.
- **`make_proxies --trim-to-cutlist` skipped a moved window on the 2k pass** (birthday reel, 2026-10-22): the 1080 pass rewrote `work/proxy_offsets.json`, so the 2k pass saw "unchanged" and kept the old 2k proxy → the two resolutions would have shown different seconds of the tail. Each footage folder now keeps its own `.manifest.json`; `make_proxies.py --res both` makes both sizes from one decode, and `doctor.py` checks that both folders were cut from the same windows.
- **One LUT for every camera** (audit 2026-10-22): every `DJI_*` file got the Pocket 4P LUT although the cache also holds the Action 4 one. The LUT is chosen per clip (`--lut-map '{"*Action*": "<cube>"}'`, the camera tag in the file, else the Pocket 4P default) and `inventory.py` shows it per clip — check the column on a mixed shoot.
- **Rotation and VFR were invisible** in the inventory: a vertical iPhone clip was listed as 1920×1080 and a variable-frame-rate clip as «60 fps». `inventory.py` reads the display rotation and the average rate and flags `VFR`.
- **Clip ids differed between NFC and NFD spellings** of the same Cyrillic name, and `check_unique` reported the file as colliding with itself. Ids are NFC-normalised and transliterated now (`clipid.py`).
- **`--lut-map '{"DJI_2000*": "none"}'` was refused** (Halloween vlog, 2026-11-01): a second Pocket recorded in Rec.709 (no D-Log) under DJI names; the "DJI footage without a LUT" gate fired on the explicit "none". The gate now skips clips whose LUT came from the map.
- **One proxy window per clip** (Halloween vlog, 2026-11-01): `--trim-to-cutlist` encodes first-used … last-used second, so beats 8 minutes apart in one 13-minute take encoded the whole span (≈70 min of 4K for 15 min used). Split far-apart groups into alias clips — a symlink `DJI_…_<id>x1_D.MP4` to the same file plus a symlink of its cleaned voice — each gets its own short window.
- **Night clips almost black on a phone** (Halloween vlog v2): the D-Log LUT leaves night street and bar footage in the mud. `night_lift.py` lifts the shadows per clip by mean luma (strong / medium / mild), tagged in the file so re-runs skip it; re-run after make_proxies re-encodes a clip (doctor warns).
- **The second camera has no D-Log** (Halloween, DJI_2000* files of a friend's camera): `work/lut_map.json` {"DJI_2000*": "none"}; actiongen grades it with the lighter Rec.709 grade.
- **`people_zones.py` timed every person box wrongly on an external volume** (found 2026-11-06): frames dumped into a temp folder under `work/` got `._00001.jpg` sidecars, which sort before `00001.jpg`; the index-based timestamps shifted and Vision got AppleDouble files. It now takes only `*.jpg` names without a leading dot. Any new loop over `os.listdir` on the project volume must do the same (`glob("*.jpg")` already skips dot files).
- **No screen recording of the event** (hermes-worker reel: the Cmd+Shift+5 recording during the challenge never started): record the public site with `site_capture.mjs` (`inputs/screens-and-images.md`) and keep the laptop screen in the camera footage for the cabinet / payment steps. Login codes, e-mail and card digits appear on screens and phone notifications in such footage — check every used range (the phone notification held the login code; that range was cut).
- **HDR phone clips came out grey and pale** (2026-11-08, iPhone 13 «HDR video» from the photo archive): HLG / BT.2020 was scaled and tagged bt709 without a conversion — the curve and the wide primaries were read as Rec.709. `hdr_lut.py` builds an HDR → Rec.709 cube fitted to Apple's own conversion (VideoToolbox; 4 code values of 255 on clips outside the fit); `common.lut_for` gives it to every HLG / PQ source, also a DJI clip shot in HLG (it would otherwise get the D-Log LUT). The LUT step must re-tag the frames (`setparams` bt709): ffmpeg 9 carries the source's HLG tags through `lut3d`, and Chrome would tone-map the converted picture a second time.
- **A Normal clip or another camera's log curve got the Pocket's D-Log LUT** (Halloween vlog v4, 2026-11-08: Action 5 Pro in D-Log M next to Pocket 4P D-Log and a friend's Pocket 4 in Normal, all named `DJI_*`): the LUT was guessed from the file name and the camera tag. DJI cameras write the colour profile into the `djmd` metadata track (protobuf; Action 5 Pro field 2.4.1, Pocket 4/4P 2.2.3.1; 0 Normal, 2 D-Log, 9 HLG, 19 D-Log M). `common.dji_profile` reads one packet of it and `lut_for` picks by (camera, profile) before any blanket `--lut`: Normal → none, D-Log M → the Action's own cube. Files without the track (re-encoded in Mimo, other brands) fall back to `--lut` / `--lut-map`, else no LUT. The cubes are DJI's own downloads (`assets/luts/README.md`); a log profile whose cube is not installed is reported as `NO LUT FOUND`, never guessed. `common.py lut <clip>` prints the reason.
